# 🎯 나만의 퀴즈 게임 (Python Console Quiz Game)

터미널에서 동작하는 Python 콘솔 퀴즈 게임입니다.
Python 기본 문법 · 클래스(객체 지향) · JSON 파일 저장(데이터 영속성) · Git 워크플로우를 직접 구현하며 학습한 결과물입니다.

---

## 1. 프로젝트 개요

메뉴에서 번호를 선택해 **퀴즈 풀기 / 추가 / 목록 / 삭제 / 점수 확인**을 할 수 있는 프로그램입니다.
추가한 퀴즈와 최고 점수는 `state.json` 파일에 저장되어, 프로그램을 종료했다가 다시 실행해도 그대로 유지됩니다.

- 언어: Python 3.10+
- 외부 라이브러리 없이 표준 라이브러리(`json`, `os`, `random`, `datetime`)만 사용
- 역할별로 클래스(`Quiz`, `ScoreRecord`, `QuizGame`)와 함수를 분리한 구조

## 2. 퀴즈 주제와 선정 이유

**주제: 한국사 기초 상식**

삼국·고려·조선·근현대사에 걸쳐 누구나 한 번쯤 배웠지만 헷갈리기 쉬운 핵심 사건과 인물을 문제로 만들었습니다.
정답과 함께 간단한 힌트를 붙여, 게임을 즐기면서 자연스럽게 우리 역사 상식을 복습할 수 있도록 이 주제를 선택했습니다.
새로운 역사 지식을 배울 때마다 '퀴즈 추가' 기능으로 나만의 문제를 계속 늘려갈 수 있는 점도 장점입니다.

**기본 제공 퀴즈 (7문제)**
1. 조선을 건국한 태조
2. 훈민정음을 창제한 왕
3. 삼국을 통일한 나라
4. 임진왜란 한산도 대첩의 장군
5. 후삼국을 통일한 고려 건국 왕
6. 1919년 대규모 독립운동
7. 발해를 건국한 인물

| 메뉴 | 기능 | 설명 |
|------|------|------|
| 1 | 퀴즈 풀기 | 문제 수를 선택해 랜덤 출제, 정답/오답 채점, 결과·점수 표시 |
| 2 | 퀴즈 추가 | 문제·선택지 4개·정답 번호·힌트를 입력받아 등록하고 저장 |
| 3 | 퀴즈 목록 | 등록된 모든 퀴즈의 문제 목록 표시 |

**📌 입력/예외 처리**

- 데이터 파일이 없거나 손상돼도 실행 가능(기본 퀴즈로 복구)

**📌 보너스 기능**
- 랜덤 출제 · 풀 문제 수 선택 · 힌트(사용 시 1점 차감) · 퀴즈 삭제 · 플레이 기록(히스토리)

## 5. 설계 개요와 클래스별 책임

이 프로그램은 역할에 따라 3개의 클래스로 나뉩니다.

| 클래스 | 파일 | 책임(대표 메서드) |
|--------|------|-------------------|
| `Quiz` | `quiz.py` | 문제 한 개를 표현. 문제 출력(`display`), 정답 확인(`is_correct`), 저장·복원(`to_dict`/`from_dict`) |
| `ScoreRecord` | `record.py` | 게임 한 판의 기록을 표현. 요약 출력(`summary`), 저장·복원(`to_dict`/`from_dict`) |
| `QuizGame` | `quiz_game.py` | 게임 전체 관리. 메뉴(`show_menu`)·메인 루프(`run`)·풀기(`play_quiz`)·추가(`add_quiz`)·목록(`list_quizzes`)·삭제(`delete_quiz`)·점수(`show_score`)·저장/불러오기(`save`/`load`) |

이 외에 `io_utils.py`는 입력·예외 처리(`get_int`, `get_nonempty_text`, `read_line`)를 담당해, 입력 검증 로직을 게임 로직과 분리합니다.

### 왜 함수만 쓰지 않고 클래스로 구조화했나?
- **관련 데이터와 동작을 함께 묶기 위해서**입니다. 예를 들어 한 퀴즈의 문제·선택지·정답·힌트(데이터)와 "정답을 확인한다"(동작)를 `Quiz` 하나에 모으면, 데이터와 그 데이터를 다루는 코드가 흩어지지 않습니다.
- **같은 형태의 대상을 여러 개 독립적으로** 만들 수 있습니다. `Quiz` 객체 7개는 각자 자기 문제를 갖습니다.
- **확장·유지보수가 쉽습니다.** 힌트 기능을 넣을 때 `Quiz`에 속성 하나만 추가하면 됐습니다.


### 메뉴 동작 흐름
```
[시작] → load() 로 state.json 불러오기
   ↓
[메뉴 출력] → 번호 입력(get_int 로 검증)
   ├─ 1 퀴즈 풀기 → 채점 → 최고점수 갱신 → save()
   ├─ 2 퀴즈 추가 → save()
   ├─ 3 퀴즈 목록
   ├─ 4 퀴즈 삭제 → save()
   ├─ 5 점수 확인
   └─ 6 종료 ┐
   (Ctrl+C/EOF 발생 시에도) → finally: save() → [종료]
```

## 7. 데이터 파일 설명 (`state.json`)

- **경로**: 프로젝트 루트의 `state.json` (프로그램 실행 시 자동 생성/갱신)
- **역할**: 퀴즈 목록 · 최고 점수 · 플레이 기록을 저장해 재실행 시에도 데이터를 유지
- **인코딩**: UTF-8 (`ensure_ascii=False` 로 한글 그대로 저장)

**스키마(구조) 예시**

```json
{
  "quizzes": [
    {
      "question": "조선을 건국한 태조는 누구인가?",
      "choices": ["이성계", "왕건", "이방원", "정도전"],
      "answer": 1,
      "hint": "위화도 회군으로 정권을 잡았습니다."
    }
  ],
  "best_score": 3,
  "history": [
    { "date": "2026-08-04 14:30", "count": 5, "score": 4 }
  ]
}
```

| 필드 | 타입 | 설명 |
|------|------|------|
| `quizzes` | list | 퀴즈 목록. 각 항목은 `question`, `choices`(4개), `answer`(1~4), `hint` |
| `best_score` | int | 최고 점수(최고 정답 수 기준) |
| `history` | list | 플레이 기록(`date`: 날짜/시간, `count`: 푼 문제 수, `score`: 최종 점수) |

> 파일이 없으면 코드에 내장된 기본 퀴즈로 시작하고, 파일이 손상된 경우 안내 후 기본 데이터로 복구합니다.

### `state.json`은 퀴즈, 최고 점수, 게임 기록처럼 서로 관련된 데이터를 하나의 파일에서 관리하기 위해 중첩된 구조로 만들었습니다.

- `quizzes`와 `history`는 여러 개의 데이터를 저장해야 하기 때문에 리스트로 만들었고, 각각의 퀴즈와 기록은 여러 정보를 함께 저장해야 하므로 딕셔너리로 표현했습니다.

- 또한 `to_dict()`를 통해 객체를 딕셔너리로 쉽게 변환할 수 있어, JSON 파일로 저장하거나 다시 객체로 불러오기도 간단합니다.

## 8. 데이터 저장 방식과 예외·복구 전략

### 왜 JSON을 선택했나?
- **가독성**: 사람이 눈으로 읽고 수정하기 쉬운 텍스트 형식입니다.
- **이식성**: 언어에 종속되지 않는 표준 형식이라 다른 프로그램과도 호환됩니다.
- **경량성 + 표준 지원**: 별도 설치 없이 파이썬 표준 `json` 모듈로 처리할 수 있고, 파이썬의 `dict`/`list` 구조와 거의 그대로 대응됩니다.
- 대안 비교: `pickle`은 사람이 읽을 수 없고 파이썬 전용이며, `csv`는 선택지·기록 같은 **중첩 데이터**를 표현하기 불편합니다. 이 규모에는 데이터베이스가 과합니다. → JSON이 적절합니다.

### 예외 처리 · 손상 복구 흐름
1. **파일 없음(첫 실행)**: 코드에 내장된 기본 퀴즈로 시작합니다.
2. **파일 손상/형식 오류**: `load()`에서 `json.JSONDecodeError`·`KeyError`·`TypeError`·`OSError`를 잡아 안내 메시지를 출력하고 기본 데이터로 복구합니다.
3. **저장 오류**: `save()`에서 `OSError`를 잡아 안내만 하고 프로그램은 계속 동작합니다.
4. **비정상 종료 방지**: `Ctrl+C`(KeyboardInterrupt)·입력 종료(EOFError)는 `ExitRequested`로 바꿔 잡고, `finally` 블록에서 저장 후 안전하게 종료합니다.

> 개선 여지(선택): 저장 직전 기존 파일을 `state.json.bak`으로 복사해 두면, 쓰기 도중 오류가 나도 직전 상태로 되돌릴 수 있습니다. 현재는 기본값 복구만 지원합니다.

- `main`은 항상 동작하는 안정 버전으로 두고, 새 기능은 **`feature/기능명` 브랜치**에서 개발합니다.
- 기능이 완성되면 `main`으로 **병합(merge)**합니다. 이렇게 하면 작업 중인 코드가 `main`을 망가뜨리지 않고, 기능별로 이력을 분리해 되돌리기도 쉽습니다.

## 10. 확장성·성능 고려사항

현재 설계는 모든 퀴즈를 `state.json`에서 읽어 **메모리의 리스트**로 다룹니다. 퀴즈가 1,000개로 늘어난 상황을 가정하면:

- **메모리**: 퀴즈 1개는 수백 바이트 수준이라 1,000개라도 1MB 미만입니다. 이 규모에서는 문제되지 않습니다.
- **저장 비용**: `save()`가 매번 **전체 파일을 다시 씀**이 잠재적 병목입니다. 변경이 잦고 데이터가 커지면 부담이 됩니다.
- **목록 출력**: 1,000개를 한 번에 출력하면 터미널이 넘칩니다. → **페이지 나눔(pagination)** 필요.
- **검색**: 키워드 검색을 추가하면 리스트 전체를 훑는 선형 탐색이 됩니다. → 잦은 검색이면 인덱스나 DB가 유리.

**개선 방향(대량 데이터 시)**: 목록 페이지네이션 도입, 변경분만 저장하는 증분 저장, 그리고 규모가 더 커지면 `sqlite3`(표준 라이브러리) 같은 경량 DB로 전환을 고려할 수 있습니다.
